## Discovery lessons

### Governance must be resolved at the right level

CANN and YuanRong expose the same failure mode in different forms. A project can have strong organization-level governance evidence while the selected action asks for a specific repository or component maintainer. TSC membership, parent-repository administration, or broad project ownership must not be projected downward automatically.

For future planner/executor work, `maintainers` actions should carry a target ownership scope such as `organization`, `project`, `SIG`, `repository`, or `directory`. This would reduce false positives and make partial results more reusable.

### GitHub Collaborator is stronger than contributor count, weaker than identity

OneDiff and Checkpoint Engine show a useful middle-strength signal. A GitHub PR listing that explicitly labels an author **Collaborator**, especially when combined with sustained release/core-code activity, is strong enough for a project maintenance edge. It is still insufficient to infer employer, legal name, or company role.

### Current-project discovery should penalize archived repositories

Intel's graph frontier initially had zero project coverage even though several well-known historical Intel AI projects exist. In 2026, Neural Speed, Intel Extension for Transformers, and Intel Extension for PyTorch are archived / retired, while xFasterTransformer and OpenVINO remain active. DISCOVER should prefer current active projects when the research objective is ecosystem frontier coverage and retain archived projects as historical context.
