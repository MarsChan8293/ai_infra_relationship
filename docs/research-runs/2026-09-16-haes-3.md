## Planner feedback

### `organization:` must count toward originating-org coverage

Run 3 exposed a deterministic coverage blind spot rather than a research failure. Both Jenga and FastDecode already had strong `organization:` frontmatter:

- Jenga: `Tsinghua University / UC Berkeley`
- FastDecode: `PACMAN Lab, Tsinghua University`

The current `project -> originating_org` template only counts `companies`, `linked_companies`, and `company`, so these projects were selected despite already carrying the answer. A follow-up planner patch should include `organization` in semantic originating-org coverage rather than forcing projects with academic origins into company-shaped fields.

### Handle-first identity remains useful

FlagTree demonstrates why governance discovery and identity resolution should stay separate. `MAINTAINERS.md` is sufficient to create strong maintainer edges for six GitHub IDs, but email strings alone are not enough to safely merge those handles with similarly named researchers elsewhere in the graph. Those identity-resolution actions can be scheduled independently later.
